# 任务文案标准框架

确认日期：2026-10-28。适用于之后所有任务。每项任务必须具备以下九项核心要素，当前示例见已认可的[开场任务设计](prologue-quest-design.md)、[河湾三项](prologue-second-main-and-side-quests.md)，以及新编的[归家与入宗两项](prologue-homecoming-and-sect-entry-quests.md)、[渔村支线旧网待潮](prologue-village-side-quest.md)。新增[青石镇树下旧凳](prologue-town-bench-quest.md)后，当前选定并成稿九项；[渔村储备与青石镇候选](prologue-small-quest-reserve.md)单独标注状态，不混入已选任务数。

| 要素 | 编写内容 |
| --- | --- |
| 1 任务名称 | 玩家任务列表与详情使用的名称 |
| 2 任务提要 | 显示在任务名称下方，用一句话提炼整项任务的核心事情；与引子分开编写 |
| 3 任务分类 | 采用现有主线／支线／人物／传承／委托／宗门／奇遇／其他类别；全部任务是汇总入口 |
| 4 任务引子介绍 | 说明当前缘由、人物需要或已知线索；可随进度更新，不提前透露尚未发生的情节 |
| 5 任务目标 | 玩家需要完成的具体事项；涉及物品时写清数量、提交对象与地点，数量未定须标明 |
| 6 任务过程 | 包含接取条件与地点、事情如何发生、主要对白、进行过程、交付与完成；必要时补充未备齐等情况 |
| 7 任务奖励 | 写清奖励内容、数量和发放时机；未定数值标注为建议或待定，没有额外奖励则明确写无 |
| 8 关联人物 | 只列人物名字，不附身份、作用或关系解释；确无关联人物时写无 |
| 9 图片描述 | 分别写大图描述与小图描述，两图独立构图绘制，供任务详情和列表使用；均贯穿任务全程 |

## 任务提要规范

任务提要位于任务名称下方，让玩家一眼看懂这项任务大致要做什么。结合任务实际写成一句简短、自然的话，可带少量情境与人物气息，不堆叠步骤、数量、奖励或背景设定，也不透露未发生的转折。

提要概括整项任务，通常在任务全程保持不变；引子介绍交代当前缘由与进展，可以随阶段更新。两者独立编写，不直接截取引子的首句，也不把当前目标或进度计数当作提要。

## 大小图规范

每个任务独立设计一张详情大图、一张列表小图。第9项「图片描述」内部区分两段，仍保持九项核心要素。两图各自固定贯穿任务全程，任务引子、目标或进度变化时，不跟着换图。

| 图片 | 暂定宽高比 | 表现重点 |
| --- | --- | --- |
| 详情大图 | 4:1 | 场景铺垫与故事气氛，主体偏右，左侧为透明过渡和文字排版预留空间 |
| 列表小图 | 3:2 | 快速辨认任务，根据主题灵活选择人物、物件组合、建筑、局部场景或风景 |

两个比例均为现阶段制作起点，实际绘制与排版时可根据需要调整，不锁定为永久尺寸。

小图不限定为单件具体事物。如果任务没有适合聚焦的代表物，或场景本身更有辨识度，就直接画景。构图须适合小尺寸阅读，重点清楚、细节适量；无需为了做成物品图标而给任务虚构关键物件。

大小图分别构图、独立绘制，通过主题、配色和美术风格保持联系。大图的左侧透明过渡不套用于小图，小图按自身画幅安排完整构图。

图片本身不烘焙任务名、提要、分类、引子、目标、进度、奖励数值或其他UI文字。示意图中的推荐等级不自动成为正式规则。配图避免直接揭示后续真相或尚未遇见的人物，完成后的任务回看继续使用各自原图。

本阶段的「图片描述」是制作说明，不代表已经生成图片或接入素材。

## 编写与核对

### 动作和场景也要成为可显示的正文

游戏无法实际演出的必要动作、观察和交代，写作「主角：（……）」「苏清禾：（……）」等角色行，括号内容直接显示在对话框；不是藏在制作备注里的动画要求。说出口的话另用引号，动作与说话可分行呈现。例如：

**主角：**（试着推开一截挡路的木头，石块却随之松动。）

**主角：**“先别动，怕是还会往下掉。”

场景信息通过角色能看到、听到或接触到的内容表达，不写全知旁白。不能讲话的小动物，其动作写在主角观察行中，不替它配对白或内心独白。接取条件、计数、节点绑定和发奖说明单独标为编写／制作说明，不当作玩家台词播放。

### 剧情插图与任务封面分开

必要的镜中景象等使用静态事件图，逐张写清主体、构图、材质、光线、禁止提前透露的信息和对应正文。每张描述一个可画出的静止瞬间，不依赖影片或连续动画。事件图按剧情翻页展示；每项任务固定的大图、小图仍贯穿全程，不能混为同一种图片。

对白应符合人物既有关系、年龄与说话习惯。语气词与emoji适量使用；行动、观察和结论要符合实际地图及已发生剧情。

任务名称、具体台词与新增数值的拟稿状态分别说明。玩家看到的介绍、目标不混入程序ID和开发备注；节点绑定、存档、物品扣除等衔接说明放在文末。记录明确的任务起点和终点，关联支线与后续主线各自结算。
