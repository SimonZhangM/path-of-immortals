# 一、S1～S5可以保留，但S3的名称和边界需要收紧

目前五类是：

| 分类 | 当前定位   |
| -- | ------ |
| S1 | 核心属性状态 |
| S2 | 通用战术状态 |
| S3 | 独立效果实例 |
| S4 | 器具专属标记 |
| S5 | 运行控制效果 |

问题在于：**S1、S2、S4、S5在程序里也都可以有“独立效果实例”**。因此，“独立效果实例”不是一个足够独立的内容分类。

例如一颗丹药施加【虚弱】，它应该归S2，不能因为来源是丹药、运行时有一个实例，就又归S3。

## 建议修正

保留S3编号，名称改为：

> **S3｜非公共临时效果**

它专门容纳：**没有必要成为公共状态，也不属于专属标记或运行控制的一段效果。**

例如：

> 某丹药提供“命中提高，持续20秒”。
> 某法器提供“下一次合格攻击获得额外强化”。

同时，数据里把下面三件事分开：

> **内容分类**：S1～S5。
> **承载对象**：角色、器具、阵盘、某个执行过程。
> **运行形式**：层数池、限时实例、次数凭证、来源维持效果等。

这样不会因为“按实例运行”，就把所有东西塞进S3。

还有一处需要纠正：**器具自身的充能、计数，不应该因为“只服务这件器具”就归入S4。**它们仍属于第一个词典的M04。S4主要是附着于目标、可被器具读取和操作的专属标记。

# 二、最需要撤回的一条：不能仅凭S分类，决定能否净化

之前我写过：

> S4默认不被普通净化处理。
> S5不是角色Debuff，所以普通净化不能处理。

这两句话都过于绝对。

尤其第三批已经把S5扩展成了“运行控制效果”，包括角色层面的麻痹、阵盘冻结和武器定身。此时再说“所有S5都不是角色负面效果”，逻辑上就不成立。

## 正确的拆分应该是

**“它属于哪类机制”和“它能被什么操作清除”是两个独立问题。**

| 对象      | 可以确定的分类 | 清除资格应怎样处理                     |
| ------- | ------- | ----------------------------- |
| 角色身上的麻痹 | S5运行控制  | 是否能被某种角色净化解除，需要明确规则，不能仅因S5就禁止 |
| 某件武器被冻结 | S5运行控制  | 普通“净化角色”不自动选中它；专门解控可以按资格处理    |
| 敌人身上的斧印 | S4专属标记  | 是否可净化、是否只能解印，需要该标记自己的规则       |
| 器具内部充能  | M04内部资源 | 不因显示一个图标就变成可净化状态              |

这里保留一个合理的边界：

> **操作的目标范围不能被偷偷扩大。**

“净化角色一个负面效果”，不应自动变成“清除其所有器具上的异常”。但这与“所有运行控制永远不能被净化”不是一回事。

对于已有麻痹、冻结、定身的具体清除资格，**当前核对的核心定案不能支持一条统一的净化结论**。应保留待确认，而不是由新分类替它们作决定。

## S4也不能成为“天然不可反制区”

“专属”表示谁使用、谁读取，不意味着天然免疫所有清除。

我建议撤回整类S4的默认豁免，改成：

> **每个专属标记必须填写清除策略；对敌人造成明显负面作用的标记，优先考虑合理反制，不因为它是专属标记就自动不可净化。**

这不是要求所有剑印都能被普通净化，而是避免以后出现一种捷径：把强Debuff改名为“专属标记”，就同时绕过容量、共鸣和清除体系。

# 三、核心状态部分有三处必须修正文案

## 1. 容量读取的是“状态持有者”，不是一律读取施加者

前面几次写“凡人使用寒霜剑，需要额外寒霜容量”，容易让人误解成：**攻击者自己没有寒霜容量，就不能向别人施加寒霜。**

应改为：

> **状态最终落在谁身上，就检查谁的对应状态容量。**

例如：

> 剑给持有者增加附炎——检查持有者的附炎容量。
> 剑给敌人施加寒霜——检查敌人的寒霜容量。

核心定案确认的是每个持有者的各状态基础容量及额外容量，不是给施加者设置一个通用“施法容量门槛”。凡人基础0仍可由合格额外容量开启持有。

**这会直接影响我们第一批凡品装备，必须改清楚。**物品使用资格、事件命中资格、目标状态容量是三道不同检查。

## 2. “灼烧不耗层概率改变”这个例子不准确

第一批C5举过：

> 灼烧不耗层概率改变。

这不是当前基础灼烧规则能够直接支持的表述。现有材料将毒蚀逐跳减层，与流血、灼烧的固定持续时间和重施刷新明确区分。

可以改成有明确依据的方向：

> 修改灼烧伤害、持续时间；
> 或修改某个**原本就消耗灼烧的具体能力**的消耗方式。

不能无意中给灼烧增加一个“每跳原本会耗层”的新前提。

## 3. “护盾不属于核心状态”不等于“它与共鸣没有关系”

雷盾是防护资源，不必改成第22种核心状态；但既有规则明确，每个存活雷盾具有10层雷蕴的等效内鸣贡献，并受共鸣读取上限限制。 

因此应写：

> **防护池不直接归入S1～S4，但可以通过已确认的专门映射参与其他机制。**

同样，“不属于Buff”不代表盾值不能被专门的破盾、转盾、扣盾效果操作。

# 四、你提出的“扰乱”实际上还没有完成定义

这是本轮发现的一个真实遗漏。

你最早给出的例子是：

> 蓄势3秒；期间受到某种扰乱Debuff，本次重击作废，重新进入CD。

但第二批虽然反复提到扰乱，最终控制表里却没有一个清楚的【扰乱】条目，只定义了“蓄势中断”和“蓄势封锁”。

这三个词不能自动等同：

| 表述          | 实际含义                   |
| ----------- | ---------------------- |
| **立即打断蓄势**  | 一次动作，结束当前蓄势            |
| **蓄势封锁**    | 一段时间内不能开始新的蓄势          |
| **获得扰乱后中断** | 某种状态成功进入后，触发被影响能力的中断规则 |

你的例子已经提出了第三种需求，但**没有同时决定“扰乱还会持续多久、是否禁止重新蓄势、是否影响其他动作”**。

因此现在应补入一条：

> **扰乱：需求已提出，具体状态形态及附加限制待确认。**

你原来的重击案例，可以先准确表达为：

> 能力的中断条件＝成功获得指定扰乱效果；
> 中断结果＝本次作废、重开完整CD。

不要顺手增加“持续沉默”“禁止全部发动”等额外能力，也不要用“获得任意Debuff”替代“获得指定扰乱效果”。

# 五、冻结、禁用、沉默的差异有价值，但还缺少“进行中的能力怎么处理”

第二批主要说明了它们能否开始新动作，但对**已经开始、尚未完成的过程**，交代还不一致。

例如：

> 法器已经蓄势1秒，还剩2秒，此刻被禁用。

是取消、暂停，还是允许蓄势继续计时但禁止落地？这会直接改变控制强度。

## 建议给每个控制补齐这一小张行为表

| 对象         | 必须填写的处理         |
| ---------- | --------------- |
| 尚未开始的动作    | 能否开始            |
| 已经进入的蓄势    | 继续／暂停／中断        |
| 已经就绪的待发    | 保留资格／封锁兑现／取消    |
| 持续维持中的领域   | 继续／暂停／终止        |
| 已经发出去的独立效果 | 是否受影响           |
| 控制解除后      | 继续剩余过程／重新等待／不恢复 |

其中：

**器具冻结暂停蓄势**可以继续作为候选标准。

**禁用如何处理既有蓄势和持续领域**，此前没有真正确定，应补为待确认，而不是继续写“全部失效”就算完成。

已经施加出去的独立效果，仍按自己的生命周期运行；但“来源维持”也要说明，维持条件是：

> 来源仍在阵盘；还是来源必须具有运行资格。

冻结时保留的静态邻接加成，与需要法器持续工作的主动领域，不应该被同一句“来源还在”混在一起。

# 六、“监听暂停”要明确暂停哪一步，否则充能法器仍然无法配置

第二批对冻结写过：

> 新的监听触发不执行。
> 监听暂停。

这可能表示两种完全不同的玩法。

假设一个法器当前火攻计数为2/3，冻结期间己方又发动了两次火攻：

**模式A：不记录。**

解除后仍为2/3，冻结期间的事件不补记。

**模式B：继续积累，只不兑现。**

冻结期间达到阈值，解除后可能立刻发火球。

两者都能设计，但不能共用一句“监听暂停”。

## 建议拆成三个字段

> **是否接收合格事件。**
> **是否更新计数／充能。**
> **是否执行已产生的触发机会。**

对于我们当前候选的“器具冻结”，我倾向于：

> 暂停新的事件记录与兑现，保留冻结前已有进度，解除后不补播冻结期间的事件。

这是**建议默认，尚不是原定案**。

特别要注意：开发日志仍然可以记录发生了什么。停止器具监听，不等于整个战斗事件系统停止。

# 七、R3“内部计时”太宽，不能冻结时一律暂停

之前把内置冷却、窗口等一起放进R3，并建议器具冻结时暂停。这个口径会产生问题。

例如：

> “最近10秒内连续完成3次攻击”。

如果被冻结后把这个10秒窗口也暂停，就相当于冻结帮它保住了原本应当过期的连击进度。

应区分：

| 计时对象            | 应怎样处理                 |
| --------------- | --------------------- |
| 入阵、轮转、某能力自身冷却   | 按控制模板明确是否暂停           |
| 当前蓄势进度          | 按蓄势控制策略               |
| 控制效果自己的剩余时间     | 随战斗时钟运行，不被自己暂停        |
| 已施加的独立药效／状态持续时间 | 按该效果自己的时钟             |
| “最近N秒”的历史窗口     | 原则上按战斗时间检查，不因器具冻结偷偷延长 |

这不需要增加R10，只要给R3、R4增加具体计时器类型。

已有同刻边界也继续保持：流血／灼烧刷新不改原跳伤节奏，到期先移除；麻痹到期与CD完成同刻时先解除麻痹。不能再被新的通用计时模板覆盖。

# 八、禁用、麻痹、跳轮的“CD到点处理”需要写成明确规则

现在的草案里：

> 禁用时CD继续，结束后可能已经就绪。
> 麻痹时CD到点跳轮。
> 下一轮封锁会吃掉一次行动。

方向上能区分，但“到点以后发生什么”还需要更准确。

## 1. 禁用：到点保留一次就绪，不反复完成CD

按照前文候选定义，禁用时CD归零以后，应当：

> 停留在就绪状态，等待禁用结束和其他资格检查。

不能因为剩余CD一直是0，就每次更新都重新产生“CD完成”事件，也不能暗中积攒三四次待发攻击。

## 2. 麻痹：沿用既有到点跳轮，不改成禁用

麻痹期间轮转CD完成会跳过本轮并重开完整CD，且已就绪手动物品和待发预备式也不能发动。

如果麻痹与冻结同时存在，冻结使CD不再前进，就不能凭空每秒发生一次跳轮。需要真实的CD完成事件，才能执行对应处理。

## 3. “跳过下一轮”与“取消下一次发动申请”不能混写

目标当前已经就绪时，这两种描述会产生不同结果。

因此下一轮封锁凭证必须明确：

> 消费于下一个轮转CD完成节点；
> 还是消费于下一次合格发动申请。

普通轮转、待发兑现、外部调用，是否都属于它要拦截的对象，也要分别填写。

**这不是增加新控制，而是把已有“跳轮”的作用节点补完整。**

# 九、沉默的“基础动作”不能由每件装备随意贴标签

之前说：

> 标为Base_Action就保留，标为Effect_Module就被沉默。

实现上方便，但设计上还不够严谨。

否则两件相同机制的法器：

> 一个把火球叫“基础动作”，沉默不影响；
> 一个把火球叫“附加效果”，沉默就完全失效。

会出现同名控制对近似物品表现完全不同的问题。

## 建议建立统一的功能角色

例如：

> **主体动作**：这件物品主要完成的动作。
> **附加触发**：命中、暴击、受击后额外产生的响应。
> **常驻修正**：命中、容量等持续参数修正。
> **维持能力**：需要持续运行的领域等。

沉默应明确封锁哪些功能角色，由设计审核判定，不能靠配置作者换标签获得豁免。

另外，**沉默某法器不应自动停止角色身上所有同属性状态**。已经存在的毒蚀、灼烧，或者已经生成的护盾，要按各自来源与生命周期处理。

“某能力不再工作”和“删除它过去造成的一切结果”是两回事。

# 十、状态容量来源被沉默／禁用后，现有层数怎么办？

这是一处以前没有接好的关键接口。

例如：

> 角色某状态基础容量10；
> 法器额外增加10；
> 当前已经有18层；
> 法器的容量增益突然失效。

此时容量变回10，已有18层怎么办？

可以设计成：

> 立即截到10；
> 暂时保留超额、禁止新增；
> 或该容量本来就是不受这类控制影响的装备固有规格。

**这三种不是等价的。**

现有定案确定了基础容量、合格额外容量，以及超量新层浪费，但不能直接据此推导“失去容量来源时怎样处理已有层数”。

所以需要增加：

> **容量增量的功能归属。**
> **容量下降时已有层数的处理策略。**

如果选择截层，还必须记录：

> 这是容量下降导致的截除，不是主动消耗，也不是敌方净化。

否则容量法器反复失效、恢复，就可能错误触发“每消耗若干状态获得收益”。

同样，恢复容量不应自动补回被截掉的层数；控制解除也不应被视为重新开战、重新发放开战资源。

# 十一、通用战术状态的重施规则，还要防止“短效果缩短长效果”和“弱效果续强效果”

第一批说：

> 同名重施刷新时间，不叠加幅度。

对于同强度、同时长的情况足够，但存在不同来源修正时还不够。

## 问题一：短效果把长效果覆盖掉

当前虚弱还剩8秒，又被施加一个持续3秒的同强度虚弱。

如果简单把剩余时间写成3秒，第二次施加反而帮助敌人提前解除。

**建议同强度默认取较晚的到期时刻，而不是无条件重设为新持续时间。**这属于新默认建议，不能回头覆盖流血、灼烧等已有专门刷新规则。

## 问题二：弱效果无限延长强效果

当前是某个高阶来源强化过的虚弱，剩1秒；普通来源再施加5秒。

不能不加说明就得到：

> 强化版虚弱，继续5秒。

这等于用廉价来源给高级效果永久续期。

我建议首版保持简单：

> **同强度可以延长有效存在时间；不同强度必须按完整来源效果处理，不把A的强度与B的时长随意拼接。**

具体是高强度整体替换、低强度忽略，还是分别记录后取当前有效最高值，属于通用状态正式落地时的一次选择。不需要现在给每种装备各自发明一套。

---

# 十二、清除操作还缺“选什么单位”和“删多少单位”的区分

第三批增加了 `Removal_Unit`，方向正确，但还少了选择粒度。

例如：

> 敌人有10层附炎，以及一个持续药效。

“随机移除一个增益”可能存在两种候选池：

> 10层附炎分别算10个候选，加药效共11个；
> 附炎整池算1个候选，加药效共2个。

这是概率结构的差异，不只是清除数量的差异。

因此应区分：

> **选择单位**：候选池按状态类型、层、效果实例还是控制来源组织。
> **移除单位**：选中以后移除一层、固定数量，还是整个实例。

现有规则已把持续药效、免疫作为独立效果整体的一个驱散单位，并规定对应单位等概率；整理新词典时必须准确继承，不能改成所有状态类型各占一个候选。

还有两个需要一并补齐的地方：

**同一实例不要跨通道重复扣除。**一个角色控制同时允许“净化负面”和“解除控制”，只是有两条合法入口，不是两份效果。一次组合清除不能重复获得两次清除收益。

**“移除独立效果”不能成为万能后门。**不能因为某状态不允许净化，就换一个更底层的删除指令绕过限制。所有普通清除最终都要检查该实例的清除策略。

风系【驱散】状态与即时移除增益动作继续分开。核心定案明确，清风涤尘命中施加驱散层，不等于当刻立刻拆掉同样数量的增益。

---

# 十三、控制范围需要补“跟随对象”和“持续覆盖对象”

第二批说控制跟随器具实例，这适合单器具冻结，但不能直接概括所有控制。

至少要区分：

| 控制范围   | 需要明确的关系                 |
| ------ | ----------------------- |
| 单器具    | 跟随该实例，移动不自动解除           |
| 格子／区域  | 谁进入该区域谁受影响，未必跟随离开的器具    |
| 武器类别   | 持续期间新入阵武器是否受影响          |
| 全阵盘／角色 | 覆盖其当前所有合格器具，不是开战时只拍一次快照 |
| 执行过程   | 只影响这一段蓄势或待发，不自动影响其他能力   |

对于持续的角色／阵盘级控制，我建议按其明确范围动态检查；不能靠换入一件新武器绕过仍在生效的控制。具体已有控制继续遵守原规则，例如定身限制的是持续期间阵盘上的武器，并阻止御兵术等外部调用。

但反过来：

> “解除一件器具冻结”

不能自动把持有者身上的**全阵盘冻结来源**整个删除。要么它只解除单器具来源，要么另有明确的“该器具暂时豁免全盘控制”能力。

位置锁定也需要补上：

> 是否同时禁止主动移出阵盘。

否则“不能移动”可以被“先拿出再放入”绕过。关系锁定则不能让已经不满足邻接条件的绑定凭空继续生效——**锁定选择与维持关系合法性仍是两个问题。**

---

# 十四、操作矩阵里的“✓”不能被理解成已经开放了全部能力

第三批把S1主动消耗、S4转换等标成“天然支持”，容易使Codex理解为：

> 这个类别内的所有状态，都默认允许这项操作。

应把矩阵含义改成：

> **该数据模型能够表达此操作，不代表所有条目已获得操作许可。**

尤其：

> 能读一个状态，不等于能消费它；
> 能消费一个标记，不等于能转移它；
> 能复制状态效果，不等于能复制来源的充能、使用次数与功法分支。

OP17“免疫／抵抗”也应拆为几个明确子行为：

> 阻止施加；降低成功概率；减少实际新增层数；缩短持续时间。

这些不是同一个百分比参数。具体怪物采用哪一种仍由怪物专题设计，不能在此默认所有Boss统一减控。现有文档也把Boss控制抗性明确留给后续设计。

六类道具适配矩阵则保留为**设计参考视图**，不是程序权限，也不是下一份品级权限矩阵的替代品。

---

# 十五、状态操作结果要比“成功／部分成功／失败”再精确一点

第三批这部分已经接近可用，但一个 `Actual_Value` 仍然不够表达所有情况。

例如：

> 灼烧已满层，追加层数为0，但持续时间成功刷新。

如果只看 `Actual_Value=0`，就会误判整次施加失败。

建议结果记录按操作类型提供实际变化：

| 操作    | 应记录的实际结果                |
| ----- | ----------------------- |
| 增层    | 新增多少、因容量浪费多少、被免疫／抵抗阻止多少 |
| 刷新／延长 | 原到期时刻、新到期时刻、是否真的改变      |
| 清除    | 实际清掉哪些实例／层数             |
| 解除控制  | 移除了哪份控制，目标是否仍受其他控制阻止    |
| 转换    | 实际消耗多少、实际产生多少、输出损失原因    |
| 修改容量  | 上限变化多少，是否影响现有层数         |

尤其“解除控制成功”不等于“器具恢复可发动”。

例如冻结解除，但禁用仍存在：

> 冻结清除成功；器具仍不能发动。

同理，**纯粹发出一个刷新请求，不应自动被当成成功新增状态**。监听器应读取自己需要的实际结果，避免靠无变化请求刷计数。

这些结果仍引用第一个词典的事件系统，不再在第二个词典建立一套独立通知机制。

---

# 十六、哪些内容必须保持原定案，不能借这次审核重做

这轮完善主要处理新词典的接口，不重开已有规则。

特别保留：

**核心状态各自的容量与共鸣读取。**不是所有状态共用一个池，也不是所有境界都读取共鸣。

**枯脉与驱散的来源处理差异。**枯脉已经明确统一池、不按层来源分账；洗尘强化的驱散则需要保留来源归属。不能为了统一Excel字段，把二者强行改成同一种账目模式。 

**状态锁值、扣层、结算顺序。**已经明确的效果先锁定所用值，再扣相应层数，最后用锁定值结算；新的转换、清除不得无意中重复消费同一批状态。

**冻结、麻痹、定身的已有边界。**新词典只是统一表达，不自动给它们添加沉默、删被动、清计数等附加效果。

---

## 给Codex的整理建议

**不需要因为这轮审校再增加工作簿，也不需要新增一大批Sheet。**在 `t01-02-状态与器具控制词典` 现有结构里补充字段、修改说明即可。

最重要的是把两种状态分开记录：

> **规则状态**：已定／建议默认／待确认／预留。
> **实现状态**：未实现／已实现／已测试。

“词典里有这个条目”“词典能表达这个操作”，都不等于它已经成为正式游戏能力。

另外，第一个词典继续负责事件、支付、时序与叠加的通用规则；第二个词典只说明**某个状态或控制选择哪些规则**。同一个刷新、清除、冻结动作不要在两个Excel里各维护一套算法。

可以把这次处理原则直接交给Codex：

> 请将本轮审校与前面三批正文一起整理。明确文案错误直接修正；新提出的默认行为保留“建议”标识；尚未确定的扰乱形态、清除资格、容量下降策略等保留待确认，不自行选择。矩阵是能力覆盖与设计参考，不自动授予每个状态所有操作权限。现有核心定案不被通用模板覆盖。

## 最终判断

**第二个词典的覆盖面已经够了，现在需要的是消除歧义，不是继续增加状态和控制数量。**

这轮最应优先处理的是：**S分类与清除权限分离、补上扰乱、补齐控制对正在执行能力与监听积累的影响，以及解决容量变化和重施规则。**

完成这些修订后，它就能更可靠地支撑后续道具设计；但我不会再把“结构齐全”说成“全部规则已经确认、所有组合都验证过”。当前更准确的名称是：

**《t01-02-状态与器具控制词典｜审校稿》——主体可用，明确保留少量需要在具体资产落地前确认的规则。**
