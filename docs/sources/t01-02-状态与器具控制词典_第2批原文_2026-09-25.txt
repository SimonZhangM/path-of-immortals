T01｜状态与器具控制词典·第2批
器具运行状态与控制 v0.9
一、首先区分两类东西
A. 持续型器具控制状态

持续一段时间改变器具运行方式。

例如：

器具冻结2秒
禁用3秒
沉默5秒
CD停滞2秒
位置锁定4秒

这类东西身上有：

开始时间 → 持续时间 → 解除时间。

B. 一次型控制动作

执行一次以后就结束。

例如：

立即打断蓄势
跳过下一轮发动
重置完整CD
取消一次待发
将剩余CD＋2秒

它们不是：

“目标身上挂着一个2秒的状态”。

所以以后不应该把“打断”做成Buff栏里的图标。

这个区分很重要。

二、器具到底有哪些“可以被控制的运行部件”

我审查以后，建议把每件器具拆成 9个运行维度。

编码	运行维度	典型内容
R1	入阵计时	战斗中途放入器具的入阵等待
R2	轮转CD	普通攻击/法器下一轮CD
R3	内部计时	监听内置CD、窗口等
R4	执行过程	延迟、蓄势、持续施放
R5	自身发动资格	自动/手动发动
R6	条件/待发兑现	反击、待发、监听触发
R7	外部调用资格	御兵术等让该器具额外发动
R8	被动/监听/领域	静态被动、事件监听、Aura
R9	位置与关系	移位、交换、绑定、阵式位置

控制效果本质上都是：

修改这9个维度中的某几个。

所以以后程序不需要每一种控制写一套完全独立的特殊代码。

三、先把三个已经确定的控制当作“标杆”

这三个不能由新词典重新解释。

1. 寒霜造成的全阵盘冻结——已有定案

现有寒霜冻结的核心效果是：

暂停全阵盘入阵/轮转CD，并阻止已就绪器具发动。

冻结期间风系CD推进/延长之类的干预不能触发；不同攻击造成的冻结时间可以累加。它不是麻痹，两者各自运行。

这里特别注意：

这是已经存在的：

角色/阵盘级冻结

而不是我们现在准备新增的：

单个器具被冻结。

不能因为名字都叫冻结，就自动把所有细节完全复制过去。

2. 麻痹——已有定案

麻痹不是CD暂停。

麻痹期间：

CD照常走。

但器具不能发动，包括：

已经就绪的手动物品
已进入待发的预备式。

如果普通轮转CD在麻痹仍存在时归零：

跳过这一轮发动，并重新开始完整CD，不补发。

资源也不会因为没有实际发动而支付。

而且已经确认：

麻痹解除和CD归零恰好同刻时，先解除麻痹，再判断本轮发动。

所以：

麻痹 = 发动封锁＋到点跳轮。

而不是冻结。

3. 定身——已有定案

现在的定身是：

只困武器。

持续期间：

武器不能使用；
入阵CD暂停；
正常轮转CD暂停；
已就绪武器不能发动；
御兵术、百兵归元等外部效果也不能调用它；
控制结束以后从原剩余CD继续；
已就绪武器恢复就绪，不重开CD。

法器、法术不因为定身本身受影响。

所以它可以拆成：

R1暂停 + R2暂停 + R5封锁 + R7封锁，目标类别=武器。

这正好证明我们现在的9维拆分是有用的。

四、由此建立第一个通用原则

以后不要再只写：

“控制目标2秒。”

而应该至少能回答：

哪些器具受影响？
哪些计时器暂停？
CD还是继续走？
就绪以后能不能发动？
外部效果还能不能调用？
被动还有效吗？
监听还工作吗？
当前蓄势怎么办？
已经发出去的效果怎么办？

这个就是器具控制词典的核心价值。

五、正式定义“单器具冻结”

这是你前面已经明确想使用的一种装备效果：

被攻击3次后，随机冻结敌方一个1×1器具2秒。

所以我们必须给“单器具冻结”一个独立定义。

【器具冻结】——建议标准定义

目标：

单个器具实例。

冻结期间建议：

R1 入阵CD：暂停
R2 轮转CD：暂停
R3 内部触发冷却：暂停
R4 已在进行的蓄势：暂停，不直接失败
R5 自身发动：禁止
R6 待发/监听兑现：禁止
R7 外部调用：禁止
R8 静态被动：保留；新的监听触发不执行
R9 位置：默认不影响

另外：

冻结期间不接受外部CD推进/延长。

解除后：

所有暂停计时从剩余值继续。

为什么我建议冻结不关闭静态被动？

这样才能和后面的【禁用】形成明显区别。

例如一件护甲法器：

相邻武器命中＋10%。

即使它被冻住：

它不能自己发动，也不会产生新的监听火球，

但原本作为“一个存在于阵盘上的辅助结构”的静态邻接效果仍然存在。

如果希望：

连它的被动都彻底失效，

那应该使用更强的【禁用】。

这样玩家一眼就能理解两者强弱差异。

冻结期间已经发出去的效果怎么办？

默认：

不追回。

例如法器已经发出一枚3秒后爆炸的延迟火种。

随后该法器被冻结：

火种仍然按自身生命周期继续。

因为它已经是一个独立生成的效果实例。

如果一个效果明确是：

“只要来源法器持续运行，领域才存在”，

那按照M07的 SourceBound 规则处理。

不能一律冻结来源就把全世界已经生成的东西全部删掉。

六、【禁用】——比冻结更强，但运行逻辑不同

冻结的特点是：

时间停住。

禁用我建议定义成：

器具仍然存在，时间可以继续走，但器具不能发挥作用。

禁用建议标准

持续期间：

R1 入阵CD：继续
R2 轮转CD：继续
R3 内部计时：继续
R4 新执行过程：不能开始
R5 自身发动：禁止
R6 条件触发/待发兑现：禁止
R7 外部调用：禁止
R8 被动、监听、领域：全部失效
R9 占格与位置关系：仍然存在

所以：

禁用结束时，如果器具CD早已完成，

它可以重新取得发动资格。

这与冻结：

剩多少CD就继续从多少走

形成明显区别。

七、禁用不能自动删除既有防御资源

这一点尤其重要。

假设一件防具在战斗开始时已经帮助角色建立了100点护甲。

它后来被禁用3秒：

不能因此直接把角色现有护甲池删掉。

因为现有护甲是一个已经建立的战斗资源池，而不是“每帧由防具重新生成”。

禁用主要影响：

这件装备接下来能不能发动、监听、提供动态被动。

如果某个特殊控制真的要：

“破坏防具并移除其护甲贡献”，

那是另一种专门效果，不能偷偷塞进【禁用】。

八、【沉默】——只封额外能力，不封基础功能

这个机制我认为非常值得保留。

例如一把寒霜剑：

基础行为：

正常剑攻击。

额外能力：

命中施加寒霜；
已有寒霜时触发某监听。

被【沉默】以后：

剑还是能砍人；

但：

特殊寒霜效果、监听、领域等暂时不能工作。

沉默建议标准

R1/R2：正常
R5 基础发动：允许
R6 额外条件效果：禁止
R7 外部调用：基础攻击仍可被合法调用
R8 被动/监听/领域：暂时失效

也就是说：

保留器具“基础功能”，封闭附加Effect模块。

九、但是“基础功能”必须由物品数据明确

这个不能凭名字猜。

例如：

武器

通常：

基础攻击属于基础功能。

附加：

命中灼烧、暴击充能等属于效果模块。

防具

基础护甲基准：

不因沉默移除。

受击反击：

可以被沉默。

法器

有些法器的“基础功能”本身就是：

每8秒发射火球。

那么沉默后是否还能发火球？

取决于这个火球是定义为：

Base_Action

还是：

Effect_Module

所以主表以后最好加：

基础动作标记。

这会让“沉默”变得可执行，而不是靠名字猜。

十、冻结、禁用、沉默三者现在形成非常清楚的关系
行为	冻结	禁用	沉默
CD继续	❌	✅	✅
自身基础发动	❌	❌	✅
外部调用	❌	❌	✅基础动作
静态被动	✅	❌	❌额外效果
监听/触发	❌	❌	❌
原有独立效果	默认保留	默认保留	默认保留
占格	保留	保留	保留

这个区分我觉得很有价值。

十一、【CD停滞】——只停CD，不等于冻结

这是一种非常干净的原子控制。

效果：

指定器具当前CD暂停N秒。

它只修改：

R1/R2中明确指定的计时器。

但：

不关闭被动；
不关闭监听；
不影响已经就绪的器具；
不禁止外部调用；
不影响位置。

所以如果目标本来已经CD=0：

单纯CD停滞不会让它失去发动资格。

这和冻结完全不同。

以后很适合做一些较轻控制。

十二、【时序锁】——禁止外部CD干预

这个可以是负面，也可以是保护型正面效果。

效果：

N秒内该器具当前CD不能被外部推进或延长。

但：

自然CD照常进行。

它不会：

把CD停住。

也不会：

阻止器具自己发动。

这种效果可以用来：

防止敌人延长CD；
也防止己方加速；
制造“无法操纵时间”的特殊器具。
十三、【外部调用封锁】

单独阻止：

其他能力调用这件器具发动。

例如：

御兵术不能选择这把剑。

但剑自己的：

正常轮转CD和自主攻击

完全不受影响。

这其实就是从现有定身规则里抽出来的一块原子机制。

未来可以设计一些：

“目标武器3秒内不能被阵式/御兵类效果调用”

而不需要把它整把冻结。

十四、【跳轮】不是状态，是一次控制动作

这点必须和麻痹区分。

跳轮

效果：

目标下一次满足正常发动时机时，本次发动取消，不支付发动成本，然后重新开始完整CD。

执行一次以后：

控制消失。

所以：

【麻痹】可以反复产生“跳轮行为”。

但【跳轮】本身不是麻痹。

以后符箓完全可以写：

“使敌方一件武器下一轮跳过。”

不需要再给对方施加麻痹。

十五、【下一轮封锁】——跳轮的持续凭证形式

如果效果现在施加，但目标还剩4秒CD：

可以给它一个：

下一轮封锁标记。

目标4秒后准备发动：

消耗该标记 → 跳轮 → 重开完整CD。

它与：

“CD＋4秒”

有非常不同的战术意义。

前者是：

保持原节奏，但吃掉下一次行动。

后者只是：

行动变晚。

这会是一个很好的高阶控制积木。

十六、【蓄势中断】也是一次动作

目标必须：

当前正在蓄势。

执行：

立即结束本次蓄势。

但：

中断以后究竟完整重开CD、部分CD、退不退款，

不由“中断”这个动作决定。

而是读取目标能力自己的：

M07失败处理。

这非常重要。

例如：

法器A：

中断后完整CD。

法器B：

中断只损失50%充能。

同一个【蓄势中断】作用到两者，结果不同。

十七、【蓄势封锁】

这是持续型控制。

持续期间：

目标不能开始新的蓄势。

但是：

普通即时攻击仍可以发动。

对于正在蓄势的目标：

我建议默认：

不追溯中断已经开始的蓄势。

如果希望立即把当前蓄势也打断：

应该写：

蓄势封锁 + 蓄势中断

两个动作组合。

这样语义很干净。

十八、【待发封锁】也要拆两种

因为“待发”有两个不同阶段。

1. 禁止进入待发

CD完成后：

不能进入待发状态。

2. 禁止待发兑现

已经待发：

合格事件出现时也不能发动。

这两种效果完全不同。

因此我建议词典里不要只写：

block_ready = true

而是分：

待发进入封锁
待发兑现封锁

十九、待发被封锁时是否丢失，不能做全局默认

例如：

已经待发的防反法器被封锁2秒。

可以有三种设计：

保留待发，2秒后继续等待；
待发取消，重新走CD；
待发保留，但期间发生的合格事件作废。

这属于具体控制/物品规则。

词典只负责：

能精确表达三种情况。

不能偷替所有器具选一个。

二十、【位置锁定】

效果：

指定器具N秒内不能改变阵盘位置。

它阻止：

手动移动；
被敌方推移；
交换位置；
强制位移。

但默认：

CD正常；
可以发动；
被动正常；
邻接效果正常。

所以它是一种：

纯空间控制。

如果某阵式要求：

三件器具保持连续排列，

位置锁定可能反而成为一种保护Buff。

因此这类控制本身不一定是负面。

二十一、【关系锁定】与位置锁定也应分开

例如：

某辅助法器已经绑定寒霜剑。

关系锁定：

N秒内绑定关系不能被更换/解除。

但寒霜剑仍然可以移动。

反之：

位置锁定

也不意味着绑定关系不能换。

这两个接口建议都保留，主要用于高阶阵式和灵品/玄品。

二十二、【器具清除】与【解除控制】

既然以后会有器具控制，就必须有对应反制。

我建议统一叫：

解除器具控制

它与角色：

净化Debuff

不是一回事。

例如一张符：

解除己方一件器具的冻结。

就是专门：

RemoveControl(FROZEN_ITEM)

可以有不同层级
指定解除

解除冻结。

随机解除一种

随机解除一个器具负面控制。

全部解除

清除该器具所有可解除控制。

控制免疫

未来N秒不能获得指定器具控制。

二十三、默认净化不解除器具控制

这一点延续上一批。

例如：

“净化自身一个Debuff”

不会解除：

寒霜剑被冻结2秒。

因为冻结的是：

器具实例，

不是角色状态栏里的Debuff。

反过来：

“解除器具冻结”

也不会清掉角色身上的毒蚀。

两套体系必须分离。

二十四、多个器具控制可以同时存在

例如一把武器同时：

冻结2秒
沉默5秒
位置锁定4秒。

2秒后：

只解除冻结。

它仍然：

沉默3秒 + 位置锁定2秒。

不能做成一个：

controlled=true

然后第一个效果结束时直接变：

controlled=false

这也是前面M07审查时非常重要的一条。

二十五、同类型控制重复施加怎么处理？

这里不能照搬寒霜的：

“冻结时长可累加”

成为所有器具控制的全局默认。

我建议每个控制类型必须拥有：

重复施加模式

标准选项：

Refresh：刷新；
Extend：叠加时长；
KeepLonger：保留较长者；
Independent：各实例独立；
Ignore：已有则忽略。

寒霜已有自己的专门“累加时间”规则。

新设计的：

单器具冻结

我们以后设计具体来源时可以决定用哪一种。

词典阶段不强行统一。

二十六、控制持续时间不能被自身暂停

例如：

器具冻结2秒。

冻结使器具CD停止。

但是：

冻结自己的2秒控制时钟必须继续走。

否则会形成：

“被冻结 → 冻结计时也暂停 → 永远冻结”。

因此：

控制持续时间使用战斗时钟。

与被控制器具自己的：

CD、蓄势等运行时钟

分开。

这是正式底层规则。

二十七、器具离阵不能成为免费洗控制手段

我建议默认：

控制附着在 器具实例，而不是当前格子。

所以战斗中：

被冻结的剑被拿出阵盘再塞回来，

冻结不会因此自动消失。

控制时间继续按战斗时钟走。

这样可以防止玩家利用：

“拔出来重插”

免费解除控制。

如果未来某个操作明确写：

“移出阵盘时清除控制”，

才作为专门效果。

二十八、来源器具失效，不自动解除已经施加的控制

例如敌方法器已经：

冻结你的剑2秒。

随后敌方法器自己被禁用。

默认：

已经施加成功的2秒冻结继续。

除非这个控制明确是：

SourceBound——只有来源持续存在才维持。

这完全沿用M07的生命周期体系。

二十九、控制抗性暂时不要在这里定数值

Boss控制抗性已经明确留到具体战斗设计，不应在T01提前给所有Boss写：

50%减控
免疫冻结

之类。

但词典要预留：

控制类型
控制强度
是否可抵抗
抗性作用方式

供T02以后填。

三十、我建议把“器具控制类型”最终整理成这张表
控制	类型	CD是否走	自身发动	被动/监听	外部调用	位置
器具冻结	持续	暂停	禁止	静态被动保留；监听暂停	禁止	正常
禁用	持续	继续	禁止	全部失效	禁止	正常

三十一、与已有三个控制重新交叉检查
寒霜冻结

不能简单改写成“器具冻结”。

它是：

阵盘级已有专门控制，

暂停全盘入阵/轮转CD和发动，并有自身寒霜触发规则。

麻痹

不能改写成“禁用”。

因为禁用时我们建议：

CD继续，但禁止运行效果；

麻痹是：

CD继续，而且每次CD到点都跳轮重开。

逻辑不同。

定身

可以用通用原子机制描述：

武器目标 + CD暂停 + 自身发动封锁 + 外部调用封锁。

但这只是：

底层表达方式统一

并不改变定身已经确定的具体玩法。

三十二、对你之前那个法器例子，现在终于可以精确写了

原设计：

被攻击3次后，随机冻结敌方1个1×1道具2秒。

现在可以写成：

M02监听：
自身被攻击的合格事件。

M04：
循环计数3次。

M05：
敌方、器具、1×1、随机1件。

M06：
施加S5【器具冻结】。

S5冻结内容：
暂停该器具运行计时、禁止发动及外部调用、监听暂停，静态被动保留。

M07：
持续2秒。

重复施加：
具体物品再选择Refresh/Extend等。

这已经是非常完整的配置语言了。

本批最终审查

我用目前已知以及未来最常见的场景反查：

冻结一个1×1法器2秒
✓ 可以精确定义。

只是让一把剑CD停2秒，但它的被动仍在
✓ CD停滞。

让一把剑还能砍人，但不能附带寒霜
✓ 沉默。

让一件法器彻底不能工作，但CD继续走
✓ 禁用。

不影响剑自己攻击，只禁止御兵术调用
✓ 外部调用封锁。

直接打断3秒蓄势攻击
✓ 蓄势中断。

未来2秒不能再开始蓄势
✓ 蓄势封锁。

跳过下一次攻击但不延长当前CD
✓ 下一轮封锁→跳轮。

防止敌方风系推进自己的CD
✓ 时序锁。

阵式位置不能被打乱
✓ 位置锁定。

冻结和禁用同时存在，其中冻结先结束
✓ 各控制实例独立解除。

目前没有发现需要新增另一套器具控制体系。

但这一批有一个需要刻意保留的边界

上面三个已有控制：

寒霜冻结、麻痹、定身

属于正式现行规则。

而新整理出的：

单器具冻结、禁用、沉默、CD停滞、时序锁、外部调用封锁、蓄势封锁、待发封锁、位置锁定等

现在的身份应是：

正式词典候选/标准语义已经定义，但并不表示游戏已经一定会做每一种。

以后我们设计物品真正用到哪一种，哪一种才进入正式资产池。

这样既给装备设计留下足够空间，又不会因为“词典里有”就把游戏强行塞满十几种控制。
