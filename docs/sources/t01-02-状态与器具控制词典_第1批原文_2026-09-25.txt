T01｜状态与器具控制词典·第1批
状态总分类＋21核心状态接口＋通用战术状态规则 v0.9
一、先确定一个总原则：不是所有“战斗中的临时东西”都叫状态

我建议以后正式分成 5类。

编码	分类	典型内容	是否进入21状态容量	是否参与七系共鸣
S1 核心属性状态	七系既有21状态	附炎、寒霜、失衡等	是	是，按现行规则
S2 通用战术状态	虚弱等跨属性公共Buff/Debuff	短时战术效果	否	否
S3 独立效果实例	丹药持续效果、免疫、某法器临时强化	一份效果一个实例	否	否
S4 器具专属标记	裂纹、剑印、猎印等	只服务某器具/套件	否	否
S5 器具运行/控制状态	冻结、禁用、沉默、蓄势中断等	控制器具运行	否	否

其中 S5下一批专门做。

另外明确：

气血、灵力、体力、护甲、灵障、特殊盾、CD、计数、充能、Combo窗口，都不是状态。

这点很重要，否则以后净化/驱散很容易误删CD或充能。

二、S1：七系21核心状态保持现有体系，不重新发明

现有体系是每一系：

1个自身Buff + 2个目标Debuff

共21种。

状态的实际容量已经正式统一为：

凡人0 / 炼气10 / 筑基20 / 结丹30 / 元婴40 / 化神50，

而且21种状态各有独立容量，不是共享一个总池；合格阵盘、法器等可以增加额外容量，超过最终容量的新层浪费。

共鸣则是另一套参数：凡人～结丹不读取，元婴每种读取10层，化神20层；不能把“实际容量40层”误写成“共鸣读取40层”。

三、21核心状态的“器具接口表”

这里不重写每个状态已经定好的完整公式，只定义：

以后武器、防具、法器、丹药、符箓可以怎样与它交互。

属性	自身Buff	目标Debuff 1	目标Debuff 2	器具设计主要接口
金	反锋	锋痕	流血	反击/反伤、武器兑现、持续伤害
木	生机	毒蚀	缠绕	恢复、逐跳伤害、火雷伤害放大
水	润脉	枯脉	寒霜	灵力/体力恢复、资源削减、冻结
火	附炎	灼烧	破甲	属性附伤、持续伤害、护甲干预
土	坚韧	疲惫	重伤	抗暴、提高被暴击率、增耗/减疗
风	轻灵	失衡	驱散	闪避、命中/追击、拆除敌方Buff
雷	雷蕴	雷印	连环	雷盾、引雷、连环闪电

这张表只是“设计入口”，不是用它替代现有规则。

例如：坚韧/疲惫、轻灵/失衡已经有明确的每层概率效果；驱散也有自己的正常拆层和额外拆层概率机制。

木系现有规则里，生机是逐跳恢复路线，毒蚀是逐跳伤害路线，缠绕则强化火/雷属性伤害并在合格触发后消耗层数；这些机制器具可以利用，但不能改写成另一套同名状态。

水系润脉/枯脉分别围绕双资源恢复和削减，寒霜则有独立触发/冻结流程。

四、器具和21状态允许互动，但需要分成6种“权限”

以后装备写效果时，我建议不再只写一句：

“与灼烧互动。”

而是明确它拥有哪一种权限。

C1｜生成

命中施加3寒霜。
成功闪避获得2轻灵。

凡品就可以少量使用。

C2｜读取

目标每有1层灼烧，本武器＋X效果。

只读，不消耗。

良品可以开始大量使用。

C3｜消耗/兑现

消耗3层锋痕，造成额外效果。

从上品开始逐渐成熟。

C4｜转换

消耗A状态，生成B状态/资源/护盾。

复杂度明显更高。

C5｜修改运行规则

例如：

灼烧不耗层概率改变；
寒霜触发方式改变；
状态持续时间改变。

主要留给上品、灵品以上。

C6｜修改容量/效率

例如：

附炎容量＋5；
驱散额外拆层概率＋X；
雷蕴容量提高。

这是法器很重要的一条路线。

但这里特别强调：

器具只是取得某种操作权限，不代表可以忽略该状态自身既有门槛。

比如零伤但成功命中的技能，若状态只要求“命中”仍可以施加；要求实际伤血、扣甲的效果则仍必须满足真实损失条件。现有系统已经明确区分这两类门槛。

五、21核心状态的通用底层规则必须继续保留

我建议在新的状态词典开头固定写四条“不可被普通器具暗中改写”的现行边界。

1. 战后全部清空

21个核心Buff/Debuff的层数和未到期时长都不跨战。

2. 状态容量与共鸣读取分离

有40层状态，不等于读40层共鸣。

3. 来源记录方式由具体状态决定

不能全局规定“所有状态都不分来源”或者“所有层都分来源”。

例如枯脉已明确使用一个统一池，不按每层来源分账。

但部分能力确实需要保留来源信息，例如某些驱散强化只作用于特定法术施加的驱散层。因此后台来源记账模式必须由具体状态/效果决定，不能一刀切。

4. 现有状态自己的生命周期优先

例如流血、灼烧已有“首次等待、固定持续期、刷新不重排下一跳、到期同刻不跳最后一下”等规则，装备不能仅凭一句“持续时间刷新”把它们改成通用状态逻辑。

六、S2：通用战术状态——正式定义规则，但暂不扩名单

这一层就是为了你前面提出的：

【虚弱】：降低攻击输出，持续一段时间。

它与七系核心状态最大的区别是：

不走层数容量，也不参与属性共鸣。

我的建议是把通用战术状态设计成一套轻量、稳定、跨装备通用的状态体系。

S2默认结构

一个普通通用战术状态默认：

单实例 + 固定效果 + 持续时间

而不是：

1～50层。

例如未来如果正式确定：

虚弱：直接伤害－20%，持续5秒。

它在角色身上就是：

【虚弱】4.3s

而不是：

【虚弱】17层。

七、通用战术状态默认不叠层

这是我很建议固定的一条。

如果再次施加同一个状态：

默认刷新剩余持续时间，不叠加效果幅度。

例如：

已有虚弱－20%，剩2秒。
再施加同版本虚弱5秒。

变成：

虚弱－20%，5秒。

不会：

－40%。

这样可以极大控制装备膨胀。

如果某个特殊物品真的需要叠加：

必须明确写成专属规则。

八、不同强度的同名战术状态，不建议自由叠加

比如：

A器具：

虚弱－10%。

B器具：

虚弱－20%。

我建议“虚弱”本身最终应该有一个标准效果定义，而不要让每件装备随意创造不同幅度。

也就是说，更推荐：

普通虚弱固定一个基础值。

高阶器具如果要强化：

修改虚弱规则/强化该状态，

而不是创造：

弱虚弱、强虚弱、超强虚弱。

这样资产库会干净很多。

九、通用战术状态不占21状态容量

所以炼气10层的状态容量不会影响：

虚弱还能不能存在。

这两套系统完全独立。

这也解决凡人阶段的问题：

凡人的21核心状态基础容量是0；如果一件凡品想施加附炎、寒霜等核心状态，就必须有合法的额外容量来源。

但凡人如果受到一个通用：

虚弱5秒

不需要先获得“虚弱容量”。

这就是S2存在的重要价值之一。

十、通用状态默认可以被净化/驱散

我建议建立统一语义：

通用正面战术状态 = Buff → 可被敌方即时驱散。

通用负面战术状态 = Debuff → 可被己方净化。

除非明确标：

不可驱散 / 不可净化。

但是这里必须再次区分：

**“即时驱散动作”**和风系核心状态【驱散】不是一回事。

风系【驱散】本身是21核心Debuff中的一种，有自己的层数和结算时钟。

十一、通用战术状态默认不记录复杂来源分账

为了避免S2也膨胀成第二套21状态系统，我建议默认只记录：

当前状态ID
当前持续时间
当前合法效果参数
最近/当前来源

不对：

每0.5秒、每一份来源

做复杂分账。

如果某件装备需要：

“只有我施加的虚弱才能兑现”

这就说明它不应该使用全局通用虚弱池，而应该用 S4器具专属标记，或者明确建立特殊来源资格。

十二、什么效果才有资格成为“S2公共状态”

这一条我觉得非常重要，否则一年以后又会冒出五十个Debuff。

我建议必须同时满足：

**语义独立。**玩家看到名字就大致知道作用。

**跨装备复用。**不是只有某一把剑才会使用。

**有稳定规则。**不会每件装备都把它改成不同东西。

**值得进入公共UI。**玩家有必要持续观察。

不符合这些条件的，就不要升级成公共状态。

例如：

“寒霜剑命中后给敌人一个只供寒霜剑下一击读取的标记。”

这种东西更适合S4专属标记，而不是创造全局Debuff【寒剑痕】。

十三、S3：独立效果实例

这个类别很有必要保留。

比如：

一颗丹药让暴击率＋10%，持续30秒。

或者：

获得一次“免疫下一个Debuff”。

它未必需要变成全游戏通用状态。

它就是：

一个来源明确、持续时间明确的Buff效果实例。

现有规则已经明确持续药效/免疫等是以独立效果整体作为一个驱散单位，而不是把里面每一个数值修改拆成多层状态。

所以以后：

丹药效果不等于必须创造新状态。

这一点可以显著控制状态数量。

十四、S4：器具专属标记

这是以后做特色武器特别重要的一层。

例如假想：

【裂纹】：由开山斧命中后留下，下一次开山斧命中时兑现。

它可以：

有层数；
有持续时间；
记录来源器具；
被特定套件读取；
战后清空。

但默认：

不参与七系共鸣；
不占21状态容量；
不属于普通净化/驱散对象。

如果某个专属标记允许被净化：

必须在标记自己规则里明确写。

这样就避免敌方一张普通净化符把所有器具内部设计全部洗掉。

十五、S5器具控制暂时只占位，不在本批定义

下一批再详细处理：

器具冻结
禁用
沉默
扰乱
CD暂停
跳轮
待发封锁
蓄势中断
位置锁定

这一批只确认：

这些不是角色Debuff，也不进入21状态体系。

因此：

“净化自身一个Debuff”

默认不能解除“某件武器被冻结2秒”。

如果某符箓专门写：

“解除一件己方器具的冻结”

那属于器具控制解除效果。

十六、我建议状态数据表以后至少有这些字段

这部分已经可以直接考虑未来Excel。

字段	示例
State_ID	CORE_FIRE_BURN
名称	灼烧

正/负面	Debuff
属性归属	火

是否占核心容量	是

S2、S3、S4都使用同一张表，但不同字段值不同。

这会比单独为每类状态再造一套Excel结构干净很多。

本批最终自检

拿几个以后真实可能出现的道具反查：

凡品寒霜剑

命中施加寒霜。

寒霜属于S1。

因此必须遵守：

核心状态容量、寒霜自己的触发机制、战后清空。

凡人若基础容量为0，还需要额外容量来源。

可表达。

良品虚弱弩

命中施加虚弱5秒。

虚弱如果以后正式进入S2：

不占核心容量、不共鸣、默认刷新时间、不叠加幅度、可净化。

可表达。

上品开山斧

命中施加【裂纹】，只有本斧能兑现。

用S4，而不是再创造公共Debuff。

可表达。

丹药

20秒内命中＋10%。

作为S3独立药效实例，不需要把“精准”强行做成公共状态。

可表达。

法器

使灼烧每跳伤害提高。

这是对S1灼烧的C5“规则修改”。

不是新Buff。

可表达。

冻结敌方1×1器具

属于S5，不会和角色寒霜/冻结混成一类。

可表达，具体规则留下一批。

这一批我认为可以先留下的核心结论

21核心状态继续是七系战斗的深层状态体系；装备可以接入，但不能另造同名规则。

通用战术状态是一套轻量的限时Buff/Debuff，不叠层、不共鸣、不占核心容量。

不值得全游戏复用的东西，不要创造公共状态，优先做独立效果或器具专属标记。

器具控制单独成体系，不和角色Debuff混合。

我认为这套分层能解决一个很重要的问题：以后我们的装备可以非常丰富，但状态栏不会随着装备数量一起无限膨胀。

下一批就可以正式做 「器具运行状态与控制词典」，把冻结、禁用、沉默、扰乱、跳轮、CD暂停、蓄势打断等逐个定义清楚。
