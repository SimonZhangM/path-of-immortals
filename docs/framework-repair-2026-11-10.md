# 战斗初始化与存档边界修复（2026-11-10）

本次处理代码审查已复现的四项问题，沿用既有资源费用、快照保护和成长规则。实施前确定以下边界，不搬迁整套内容目录、不调整怪物数值。

1. `BattleSimulation` 默认明确使用现行规则，只有显式 `legacy_fixed_defense=true` 才进入历史模拟。移除以某件地图库存物品是否注册作为规则开关的判断；校验注册器及书术依赖，并保留初始化失败，禁止 `start()` 用后续检查覆盖错误。
2. `MapLoadoutStore` 共用快照转工作会话入口。地图和独立战斗先完成恢复，再将可见快照写入内部会话；写成功后才发布新路径，失败保留原快照和活动路径。已有工作会话不重新复制。
3. `GameManager` 持有待提交的消耗快照。保存失败冻结模拟，恢复／重新开战之前重试同一快照；成功才解除存档阻塞。失败期间禁止配装变更，避免后续操作改变重试内容；不回退消耗，不重复扣除。
4. `MapLoadoutState.restore` 在学习与任务派生之前补齐缺失／空的旧成长数据，沿用原地图的初始境界、满基础资源及配置经验；入口可显式提供已有成长作为旧档默认值。非空畸形成长仍拒绝，后续布局校验失败恢复原成长、境界及学习。空路径／缺文件初始化采用同一默认逻辑，快照迁移仅写工作会话。

验证使用隔离 APPDATA／LOCALAPPDATA 和测试目录，覆盖原复现条件、失败重试、源快照不变、当前成长保留及失败恢复原状，并运行直接相关战斗／地图衔接检查。验证结果完成后记录于 PROJECT_PROGRESS，真实存档不参与测试。
