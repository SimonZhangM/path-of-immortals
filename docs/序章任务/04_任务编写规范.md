## 任务编写规范

确认日期：2026-10-28。适用于之后所有任务。每项任务必须具备以下九项核心要素，当前示例见已认可的[开场任务设计](01_序章任务正文.md#主线一-药香如常)、[河湾三项](01_序章任务正文.md#主线二-河湾逢险)，以及新编的[归家与入宗两项](01_序章任务正文.md#主线三-潮声归处)、[渔村支线旧网待潮](01_序章任务正文.md#支线三-旧网待潮)。新增[青石镇树下旧凳](01_序章任务正文.md#支线四-树下旧凳)后，当前选定并成稿九项；[渔村储备与青石镇候选](03_储备与候选任务.md#储备与候选任务)单独标注状态，不混入已选任务数。

| 要素 | 编写内容 |
| --- | --- |
| 1 任务名称 | 玩家任务列表与详情使用的名称 |
| 2 任务提要 | 显示在任务名称下方，用一句话提炼整项任务的核心事情；与引子分开编写 |
| 3 任务分类 | 采用现有主线／支线／人物／传承／委托／宗门／奇遇／其他类别；全部任务是汇总入口 |
| 4 任务引子介绍 | 说明当前缘由、人物需要或已知线索；可随进度更新，不提前透露尚未发生的情节 |
| 5 任务目标 | 玩家需要完成的具体事项；涉及物品时写清数量、提交对象与地点，数量未定须标明 |
| 6 任务过程 | 包含接取条件与地点、事情如何发生、主要对白、进行过程、交付与完成；必要时补充未备齐等情况 |
| 7 任务奖励 | 写清奖励内容、数量和发放时机；未定数值标注为建议或待定，没有额外奖励则明确写无 |
| 8 关联人物 | 只列人物名字，不附身份、作用或关系解释；确无关联人物时写无 |
| 9 图片描述 | 分别写大图描述与小图描述，两图独立构图绘制，供任务详情和列表使用；均贯穿任务全程 |

## 任务提要规范

任务提要位于任务名称下方，让玩家一眼看懂这项任务大致要做什么。结合任务实际写成一句简短、自然的话，可带少量情境与人物气息，不堆叠步骤、数量、奖励或背景设定，也不透露未发生的转折。

提要概括整项任务，通常在任务全程保持不变；引子介绍交代当前缘由与进展，可以随阶段更新。两者独立编写，不直接截取引子的首句，也不把当前目标或进度计数当作提要。

## 大小图规范

每个任务独立设计一张详情大图、一张列表小图。第9项「图片描述」内部区分两段，仍保持九项核心要素。两图各自固定贯穿任务全程，任务引子、目标或进度变化时，不跟着换图。

| 图片 | 暂定宽高比 | 表现重点 |
| --- | --- | --- |
| 详情大图 | 4:1 | 场景铺垫与故事气氛，主体偏右，左侧以较简洁的完整环境衬托，整图不透明 |
| 列表小图 | 3:2 | 快速辨认任务，根据主题灵活选择人物、物件组合、建筑、局部场景或风景 |

两个比例均为现阶段制作起点，实际绘制与排版时可根据需要调整，不锁定为永久尺寸。

2026-10-29制作记录：九项已选任务当前大图实际均采用3:1，小图3:2；原4:1保留为早期起点，不作为现有成品的验收尺寸。九项18张现行图均已获用户确认，集中于[序章任务配图](../../output/imagegen/序章任务配图/README.md)的「已采用」；旧版移入「未采用」，提示词和检查移入「制作记录」。后续任务仍可按画面与排版调整。

小图不限定为单件具体事物。如果任务没有适合聚焦的代表物，或场景本身更有辨识度，就直接画景。构图须适合小尺寸阅读，重点清楚、细节适量；无需为了做成物品图标而给任务虚构关键物件。

大小图分别构图、独立绘制，通过主题、配色和美术风格保持联系，分别按自身画幅安排完整构图。

**2026-10-29最新统一要求：所有任务大图、小图均正常绘制，整张不透明；明确禁止透明渐隐、边缘淡出、半透明蒙层或以白雾模拟渐隐。** 此条覆盖此前大图左侧透明过渡的要求。左侧可通过简洁构图和自然明暗降低视觉干扰，仍须保留完整画面。生成提示词明确写入“fully opaque image; no transparency, no alpha fade, no edge fading”；不得在导出或接入时自行补回渐隐。

图片本身不烘焙任务名、提要、分类、引子、目标、进度、奖励数值或其他UI文字。示意图中的推荐等级不自动成为正式规则。配图避免直接揭示后续真相或尚未遇见的人物，完成后的任务回看继续使用各自原图。

「图片描述」是制作说明；生成状态以各任务第9项的实际文件链接为准，图片已生成也不代表已接入游戏。

### 画风与剧情氛围（2026-10-29补充）

出具剧情配图描述前，须同步阅读对应任务的引子、目标、完整过程与对白，以及用户最新补充；明确画面取自哪个剧情阶段，再核对地点、人物是否在场、器物类型与损坏状态、物品分布及事件因果。不能仅凭任务名称或旧图片描述设计。“不提前揭示秘密”不意味着抹掉任务的核心现场事实：例如《商路惊魂》应呈现马拉货车遇袭后马逃走、车体破损、货物散落，不能画成完好货车安静停靠。剧情与配图说明冲突时，先按已确认剧情修正说明，再同步生成提示词、大小图及现行预览入口。

配图还须表现任务成立的关键原因，例如旧网被礁石挂住、长凳需要加固、遇袭现场留下血迹和战损。主角或NPC可以不入画，但相关痕迹不能因此一并省去。少量可数、直接代表交付凭证的物件，数量须与目标一致；伤人者身份等未揭晓信息则保留画外。固定封面可选任务中一个有代表性的阶段，不要求一张图塞进全部过程，也不因一次危险任务就给所有日常任务添加破损或血迹。

用户认可《药香如常》[大图v04](../../output/imagegen/序章任务配图/已采用/主线01_药香如常_大图.png)的画面表现。后续沿用青石镇地图的细腻手绘质感、清楚轮廓、可辨材质与自然空间关系；光照、色温、天气及明暗反差须根据每项任务的实际剧情分别设计，不能把这张的高亮暖阳当作所有配图的固定效果。

每份图片说明分别交代主体与构图、时间／环境、情绪、光源和色调。温暖日常、阴湿山林、幽暗旧祠、平静海边、夜间灯下等场景应有相应差异；气氛服从已定剧情，未定天气不擅自变成剧情事件。暗景也要保留主体辨识度，不能用整幅模糊或泛白蒙层代替氛围。自然水雾等只在场景确有需要时局部表达。

固定贯穿任务的大小图选取能代表任务的氛围，不因每个阶段切换光线或另换封面。大小图保持美术与叙事联系，可各自调整取景与照明，避免全套使用相同的强阳光、窗格光斑或金黄色调。

主线一最新比例为3:1，视觉重心在右半部；不将这项任务的具体比例及晨光配置自动推广到其他任务。正常不透明、无透明渐隐则是所有任务大小图的统一要求。提示词与参考图按各版本保存，后续迭代先保留已认可画风，再明确本次需改变的构图或氛围。

## 编写与核对

文档采用普通Markdown标题与标题链接，不插入空HTML定位标签。需要调整标题或目录时同步更新引用；相同标题的自动编号按所在文档核对，避免阅读器将标签显示为代码或异常链接。

### 动作和场景也要成为可显示的正文

游戏无法实际演出的必要动作、观察和交代，写作「主角：（……）」「苏清禾：（……）」等角色行，括号内容直接显示在对话框；不是藏在制作备注里的动画要求。说出口的话另用引号，动作与说话可分行呈现。例如：

**主角：**（试着推开一截挡路的木头，石块却随之松动。）

**主角：**“先别动，怕是还会往下掉。”

场景信息通过角色能看到、听到或接触到的内容表达，不写全知旁白。不能讲话的小动物，其动作写在主角观察行中，不替它配对白或内心独白。接取条件、计数、节点绑定和发奖说明单独标为编写／制作说明，不当作玩家台词播放。

### 剧情插图与任务封面分开

必要的镜中景象等使用静态事件图，逐张写清主体、构图、材质、光线、禁止提前透露的信息和对应正文。每张描述一个可画出的静止瞬间，不依赖影片或连续动画。事件图按剧情翻页展示；每项任务固定的大图、小图仍贯穿全程，不能混为同一种图片。

对白应符合人物既有关系、年龄与说话习惯。语气词与emoji适量使用；行动、观察和结论要符合实际地图及已发生剧情。

任务名称、具体台词与新增数值的拟稿状态分别说明。玩家看到的介绍、目标不混入程序ID和开发备注；节点绑定、存档、物品扣除等衔接说明放在文末。记录明确的任务起点和终点，关联支线与后续主线各自结算。
