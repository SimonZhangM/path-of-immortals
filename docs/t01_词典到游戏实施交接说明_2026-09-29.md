## 1. 起步时先弄清三件事

1. **08是具体物品清单，01～07是解释、约束和支撑这些物品的词典。**不能把八个Excel的每一行都转换成一件物品或一个运行效果。

## 4. 哪些写入游戏，哪些保留在开发资料

| 信息性质 | 处理方式 | 例子 |
| --- | --- | --- |
| 已明确的物品静态数据 | 映射为有类型的内容定义，供注册器校验 | 青石短剑11伤／5.5秒／体力3，尺寸1×2；品级下品 |
| 通用运行语义 | 由共享逻辑解释数据，避免逐物品专用脚本 | 命中后施加、实际气血受伤后施加、资源费、耗尽移除、战后清空 |
| 已配置的关系 | 单独记录ID引用、资格及奖励，不靠名称猜 | 六项升品成员身份、正交邻接、最低品级奖励版本 |
| 设计许可和适用约束 | 用于导入／开发校验；确需战中使用的部分才进入运行数据 | 品级许可、字段适用、例外名单、机制复杂度审核 |
| 展示信息 | 从同一权威定义生成名称、数值和简短说明 | 品级、元素标签、毒蚀说明；UI不重新计算伤害规则 |
| 派生统计与名义试算 | 作为核对或测试预期，避免重复成为战斗加成 | 总占格、护甲权重、DPS、21状态来源数、组合总上限 |
| 候选且有明确目标的资产参数 | 获授权后可进入测试版本，保留版本与待平衡标签 | 本轮27下品r1、88凡品；不能据此称平衡已完成 |
| 建议默认、未决机制、空白参数 | 不启用相关未完成路线；仅暂停依赖它的部分 | 单叠上限数值、未定配方费用、未来独立套装主动能力 |
| 原文、审查过程、概念案例、停列记录 | 保留出处与开发追溯，不注册成游戏内容 | M条目示例、W13火羽弓停列、旧31上限、旧测试数值 |

“不写成运行字段”不等于可以忽略：例如品级权限应当约束内容合法性，数值试算可以帮助检查转换是否正确，历史记录用于解释迁移原因。

### 转换时必须明确的技术约定

- **身份分层：**`t01.asset.*`是设计记录ID，W33等是来源编号，中文名是展示名；现有`base.map_item.*`是已用游戏ID，库存单位另有实例ID。新线程建立显式映射，保留旧ID及存档引用；同名、同品级不能替代身份判断。新的游戏命名空间遵循现有约束，一旦使用就稳定维护。
- **字段分层：**物品定义、某个库存单位、阵盘中的一叠、战斗运行实例是不同对象。CD进度、剩余数量、状态池、当前护甲不能回写为共享物品模板的数值。
- **效果不是自由文本执行：**将“行为＋时机＋资格＋目标＋费用＋生命周期＋来源”映射到明确的共享处理器。未知效果或引用应报出资产ID及来源位置，不静默略过，也不只留下说明文字。
- **空值、0、NONE分开：**空白先按字段适用性区分“不适用”和“未定”；0是已配置的零值；NONE是明确无元素，并参与防御元素统计。无周期能力不能因空CD被补0而进入零秒轮转；若沿用旧格式对纯被动写0，必须同时保证它没有周期调度，必要时增加明确的发动类型。
- **单位转换：**表中CD为秒，当前模拟内部用微秒；资源落账和层数取整分别查规则。表中的灵力映射到现有`spirit`资源，不另造一套与它并行的mana。定义中的基础体力费与支付时的加算修正分开，不能因为旧字段是整数就截掉25%增耗。
- **公式读取：**可分别读取公式文本与缓存结果，核对依赖；缓存为空或过时要重算或报错。不要把`='某表'!J6`字符串写进运行JSON。组合收益与动态权重按实际装备关系计算，不能将整组统计常量重复发给每件成员。
- **实施来源记录：**建议在开发映射表记录文件名、表名、记录ID／单元格、文件校验值、目标游戏ID、依赖、实施与测试状态。它服务于追溯，不要求每个字段进入玩家存档。

## 9. 验证与交付要求

### 数据与行为的验收

先核对有效集合数量：下品9武器＋8防具＋4法器＋6丹药＝27，凡品27武器＋28防具＋18法器＋10丹药＋5暗器＝88，符箓0。有效资产ID唯一，效果与关系引用可解析，停列内容未回流；每批导入只核对本批，但全量清单不能漏项。

按本次改变运行直接相关验证，典型案例包括：

- **加载链：**源定义里的品级、攻击类型、元素、费用及效果通过地图转换后仍正确；未支持效果明确拒绝；新增定义不会自动增加正式库存或重复剧情奖励。
- **丹药：**首瓶0秒具备资格但不强制服用；满资源等待，实际服用后开始CD，2／4／6秒跳药效；最后一份消耗移除后既有恢复仍继续。分叠时核对库存守恒、独立CD和同款持续恢复限制。
- **防具：**NONE也投元素权重；甲型和元素并列的决胜规则不同；多盾、部位限制、邻接／拆解、混品取最低奖励均正确；无免费补满和奖励重复叠加。
- **灵障：**容量、加法、溢出、吸收范围与顺序；灵障珠满值停用，普通灵障因攻击减少后完整CD重启；仅雷盾减少不能误唤醒本件。
- **状态与受击Buff：**命中和实际损失门槛不同；新层何时可用按状态各自定义；9秒受击计时与回甲CD分离，雷蕴成功施加后立即转盾也算成功；死亡／免死、控制／恢复不产生多余事件。
- **资源与时钟：**多武器费用在支付时修正，同刻恢复／消耗顺序稳定；暂停、倍速和重新装配不制造重复结算；无周期项不进入0秒事件循环。
- **存档与UI：**原物品ID和持有单位保持，未使用库存不丢失；显示来自同一权威数据。只在本次确实改动交互时运行相关鼠标测试。

这些是测试方向，不授权根据假想问题修改已定机制。名义DPS、总恢复量和状态覆盖率的算术通过不等于真实战斗平衡通过。
